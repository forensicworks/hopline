Analysis

Patterns in the transactions that are loaded. They are guesses: each one says why, none proves who owns what.

What was found is listed in the Findings panel on the right, and counted in the strip of chips at the bottom of the graph, just above the time line, which carries the counts of what is loaded and shown. Point at a chip or at a row of the Findings or Detections (or focus it with the keyboard) to see where it is: the vertices it stands for get a ring in the finding's colour and the rest of the graph fades until you move away, and its tooltip says how many of them are on screen. Point at a vertex to see which chips and rows count it. This only looks: nothing is selected, loaded or moved.

Assistant

The findings come from the analysis; an assistant only reads, ranks or words them, and every id in its answer is checked against the evidence. Everything loaded is included, hidden or not. Nothing here leaves this computer: the only model it asks is one on this computer, set up below.

The first three selected transactions or wallets, and any transaction id, address, peel chain (P-…) or cluster (C…) named in the question, are given to the model in full. The rest is the usual cut-down evidence, so it can only answer from what is loaded. Ctrl+Enter asks the local model. The question is not saved with the workspace.

Local model

Works with a server on this computer that speaks the OpenAI chat format: Ollama, LM Studio, the llama.cpp server. Only localhost, 127.0.0.1 or ::1 is accepted, so the evidence never leaves the machine, and no key is sent.

Most local models read only about 4,000 tokens unless you raise their context window (in Ollama, num_ctx). If the answer ignores the end of the evidence, lower the pattern rows above or raise the context. If the browser blocks the request, allow this page's address in the server (for Ollama, the OLLAMA_ORIGINS setting).

Prices come from the mempool.space price history, whose resolution varies: when measured it had one point a week before March 2023, one a day until January 2024 and hourly points after, but the server has also returned denser data. A price interpolated across more than two days is shown with ≈ and is rough (in spot checks weekly-era values were several percent off the market that day). External sources

Look-ups happen only when you ask, for one wallet at a time: right-click a wallet, or use the button in its details. Nothing is looked up for the whole graph. Each source keeps its answer on the wallet, none is applied by itself, and the report names every source that was asked.

Arkham Intelligence

Arkham's API cannot be called from a web page (it sends no CORS headers), so a small program on your machine, tools/arkham_proxy.py, makes the call. It keeps your API key in an environment variable: the key never enters this page. Each look-up sends the wallet's address to Arkham. Switched off while the data source is Tor. Without a key, Check in Arkham in the right-click menu and the details opens Arkham's own page in a new tab instead (your own Arkham account, if you are signed in there).

Label packs
Built in

Lists that come with this page, from the source named on each: they are read from files on this same site and nothing is sent anywhere. The sanctions list is on until you switch it off; the others are off until you switch them on. Each row says how old its data is, and the choice is kept in this browser. A listing is that list's claim, not proof.

Your own packs

Lists of wallets with names (an exchange's addresses, a sanctions list, your team's findings) from a CSV or JSON file. They are other people's claims: shown as "known (pack name)", kept apart from your own labels, and never sent anywhere. Addresses are checked (checksum included) when the file is read.

Sanctions list (OFAC): download SDN_XML.ZIP from OFAC's SDN list page and choose it here: it is read in your browser and turned into a pack of the Bitcoin addresses it names. SDN_ENHANCED.ZIP and SDN_ADVANCED.ZIP (or their unzipped .XML files) work too but are several times larger. Not SDN.CSV: it cuts long entries and loses addresses. The list changes whenever OFAC acts, and the built-in copy is only as new as its date: import the file to use a newer one (a pack with the same name replaces the built-in one).

Expansion limits

Public APIs rate-limit. When a limit stops an action the graph keeps what was loaded and says so.

Privacy

Saves the graph with your labels and notes in the browser's local storage, unencrypted, so a reload does not lose work. Untick it on a shared machine; unticking deletes what was saved. Export is always explicit.

Help

Focus shows one transaction or address and what is around it (depth = steps away). Double-click a vertex, or click a row under Funded by / Spent by / Transactions in the details, to move there; ◀ ▶ (or Alt+←/→) go back and forward through where you have been. Untick Focus to see everything loaded.

Addresses can be pasted in any case or as an explorer link; bc1… is lower-cased for you, legacy 1…/3… addresses are case-sensitive and checked before anything is sent.

Click a vertex to inspect it. Without Focus, double-click loads its neighbours. Drag a vertex to pin it; drag the background to pan; scroll to zoom. On a touch screen, one finger pans or moves a vertex, and two fingers pinch to zoom and pan.

Edges run in the direction money moves. Width = amount (log scale). Dashed = output not spent yet. Each edge is one coin; several coins between the same two vertices (say 14 inputs of one transaction from one wallet) are drawn as one arrow labelled "14 inputs · total": click it for the list of coins, or untick One arrow for coins between the same two vertices under View to draw each coin.

Shape size shows value (a transaction's total output, a wallet's total received). Under View, Proportional makes the area of a shape proportional to its value, Compact uses a log scale where sizes differ little (values within a factor of ten of each other get similar sizes), and Auto uses Proportional in the Force layout (and the trace's Force and Timeline + force arrangements) and Compact elsewhere. The Force layout leaves room for the shapes.

Squares are transactions (hollow = not loaded), circles addresses, diamonds coinbase, hexagons OP_RETURN.

Trace (under Layout) shows one wallet or transaction. Click ▶ beside it to show where the money went, ◀ for where it came from; each click moves one wallet along the chain and the vertices already on screen stay put. Double-click = ▶, [ ] = ◀ ▶ for the selected vertex, Ctrl+Z takes a step back, right-click for Hide this branch. Nothing is ever removed by a click. When an arrow has more than 5 behind it (change this under Expansion limits), the click opens a list instead of flooding the screen: the top few come ticked (the largest, unless you chose another order), and you can sort it (largest, smallest, newest, oldest: your choice is remembered), narrow it by amount or date, and see who is on the other side. Hover an arrow for the count, total and dates behind it; Shift-click always opens the list. Select vertices (Shift-click, or Ctrl+A) and use Hide selected / Keep only selected; right-click gives Hide this vertex, Hide this branch and Select this branch. Dragging one of several selected vertices moves them all together. Opening a new wallet or transaction adds it as another starting point; Start over from here replaces the trace. Ctrl+Z undoes any of these.

Arrange (in the Trace layout's bar): A trace starts in Columns, which keeps the vertices where you put them. Flow lays out exactly the vertices you traced left to right in the direction the money moves (go back to Columns and every vertex returns to where you had put it), Timeline spreads them over time (left to right), Timeline + force does that and also pulls connected vertices to the same height so a chain runs straight across and branches fan out above and below it, Force pulls connected vertices together in any direction, and Time × amount spreads them over time with the bigger amounts higher up, on a log scale with a scale at the left. What is shown is still only what you revealed; the other arrangements place it all again each time you add something, Columns never moves what is there. Where x is time a transaction can only be dragged up and down, so it stays at its time; hold Shift to move it sideways. Wallets have no time of their own and drag anywhere.

Selecting and hiding work in every layout. Click, Shift-click to add, or drag a box (Shift-drag, or switch ⬚ Box on with B); Select ▾ picks everything, all wallets, all transactions, everything above an amount, or a tag; Ctrl+A selects all on screen. Hide selected (or Delete) takes them off the screen without deleting anything, Keep only selected hides the rest, Hidden (n) shows some or all of them again, and Ctrl+Z undoes. Hide is not Delete: Shift+Delete (or Delete from workspace, in every layout including a trace) really deletes a vertex from the workspace, and the message offers Undo (so does Undo load in the top bar).

The time axis along the top of the Timeline layout and of the trace's time arrangements is a line with ticks and timestamps. Hover it to read the exact time under the pointer; hover a transaction and its exact time appears on the line. Inside a shortened (Compact) gap the time shown is only interpolated and is marked ≈. In the trace's Columns arrangement the line carries a timestamp over each transaction instead of a scale, since the columns are not time.

Time line: the scale shows the span of what is on screen; each dot is one transaction at its exact time (hover for the timestamp, click to select it; click a bar to select the transactions in it). Drag the two handles to show only a time window; T or the arrow folds the bar away.

Backup server: with mempool.space or Blockstream.info chosen, If it keeps failing, use … instead (on by default) lets the other one answer when the first throttles you (HTTP 429), fails or does not answer: a throttled request moves at once, other failures after one retry, and the failing server is left alone for about a minute. The message says when it switches, and each transaction keeps the server that actually sent it (the report lists both). The backup sees those look-ups too: turn the option off to keep everything on the one server. It is never used with Tor or your own server.

Key for your own server: with My own Esplora URL chosen, an optional key or token is sent with every request to that server, in the header you name (Authorization by default). It never goes to another server, into an address, an export or a report, and is forgotten when the page closes unless you tick Remember on this computer; a server that refuses it (401 or 403) is reported as that. Requests at once and Pause between starts set the pace.

A wallet's transactions in the details are told apart: ↓ in (green), ↑ out (pink) and ↔ self, each with who is on the other side, the date and the amount. All / In / Out filter them, the order can be newest, oldest, largest or smallest first (or known or labelled first), show and unspent only narrow it as in the arrow list, hovering a row outlines it on the graph, and + show puts just that transaction on the trace (in the other layouts, onto the graph). Tick rows (or all listed) to act on several at once: Show on graph and As one vertex in a trace, Show on graph and Select on graph elsewhere, and Copy ids. Change that came back to the wallet is netted off.

Time bar and arrows: with the time bar narrowed (drag its ends), the arrows in the Trace layout count and show only what falls inside that range, because what is outside would not be drawn; the tip says how many more are outside, and a transaction whose time is unknown is kept. Switch it off under Expansion limits. In a trace you can also drag across the time line's graph to choose a stretch of time for the arrows alone (that hides nothing); Show only this range on its chip makes it the time bar's window, which does hide what is outside, and the × clears it. In the arrow list, show narrows to skip known services or only known or labelled wallets, unspent only keeps outputs not spent yet (where that applies), and Known or labelled first is an order.

Group vertex (Trace layout): several hidden neighbours of a vertex can stand on the trace as one vertex (a stack of cards). Make it from a group in a wallet's Transactions or in the arrow list (◼ as one, or Ticked as one). Select it to see every member; Show the largest, Show all and Choose which… put members on the trace; double-click shows the largest few. It is only a way of showing hidden vertices: it is not in the graph or the exports, and the report lists every member. A group can have a label, a tag and a note, and Undo after an auto-expand puts a vertex back in its group.

Grouping: three or more rows with the same wallet on the other side, or three or more small ones (under the limit in Expansion limits), fold into one line in a wallet's Transactions and in the list behind an arrow: "12 transactions to bc1q… · 2022-03 → 2022-06 · 0.0001 to 0.002 BTC each". Click it to list them, copy their ids, or (in a trace) put the largest few or all of them on it; in the arrow list its box ticks them all. Nothing is hidden: every row stays one click away, and Group similar rows switches it off. Group rows by (Expansion limits) can fold by month, week, day or year instead. Outside the Trace layout, rows that the Focus view keeps off the screen can stand as one vertex beside their wallet (◼ as one, or As one vertex for ticked rows); open it to show them, which switches the Focus view off.

Copy: every address and transaction id has a small copy icon beside it (in the details, the lists under it, the balances, the clusters, the Previous/Next list and the bar under the graph); the right-click menu has Copy txid / Copy address, and Ctrl+C on the graph copies the selected addresses and transaction ids, one per line (when no text is selected). With several selected, the details offer Copy n addresses and Copy n transaction ids.

Find (the field in the top bar: click it, or press Ctrl+F while the canvas is focused) searches what is already loaded, on screen or not: any part of an id or address, your label, tag and note, a block height, a name from the built-in list or a label pack, or a cluster such as C3. Several words must all match. ↑ ↓ choose, Enter goes to it (a vertex that is not shown is brought in: in a trace as another starting point, which Undo takes back), Esc closes. An id that is not loaded yet offers to add it.

Undo and Redo: ⟲ Undo (Ctrl+Z) takes back the last step: in a trace a reveal, a hide, a group, an added starting point, a start over or a Re-layout; in the other layouts a hide or a Re-layout. ⟳ Redo (Ctrl+Shift+Z or Ctrl+Y) puts back what Undo took away; doing something new ends the chain. Re-layout places everything again and releases the vertices you dragged, and is one Undo step.

Adding: once something is open the top box says Add. In a trace what you add becomes another starting point; several ids or addresses can be pasted at once (up to 10). Shift+Enter or Shift-click starts over with it instead.

Undo load (top bar) takes back the last thing that changed what is loaded: opening or expanding something, an auto-expand, an import, a removal or Clear, with the graph, the focus and the trace as they were. The message of every load, import and Clear carries an Undo button for a few seconds (a big load, longer), and the two buttons are in the bar only while there is something to undo or redo. Use it when a very large wallet or transaction was loaded by mistake; press Cancel first if it is still loading. It keeps the last 10 changes in memory only, and a change too large to copy cannot be undone. ↷ Redo load puts back what it took away, until something changes what is loaded. The Undo and Redo buttons of the Trace bar are separate (hides, reveals, groups and layout changes) and name the step they will take back when you hover them.

Balance: a wallet's details show what the server says it holds now, with when it was read. Selecting one wallet reads it by itself (switch that off under Expansion limits); Load balance reads just that (one request); select several wallets for a list of balances and their total, and Load n balances for the ones not read yet. Received here and Sent from here count only what is loaded in the graph, so a wallet can hold 0 and show nothing sent: it spent its coins in transactions not loaded yet (the details say so; Show forward or Load history fetches them).

Update from the chain (the ↻ button in the top bar, next to Import): a file or a session shows the chain as it was when it was made, and a wallet whose history was loaded is not asked about again. it asks the server again, never from what the browser kept, about what can have changed: each wallet whose totals were read (one request; its newest transactions are read only when the totals differ, until one already held is met, 100 at most), each transaction that was unconfirmed, and each transaction with an output recorded as unspent. Labels, tags and notes are untouched, the new transactions next to a wallet on the trace are shown, a note in the time bar lists them (Select the new), and Undo load takes the update back. A wallet's details have Check for new transactions for that wallet alone, and an unconfirmed transaction has Check for confirmation. When a file made more than 10 minutes ago is opened, a bar offers the update and says about how many requests it takes; nothing is asked until you press it, unless Update from the chain when I open a file (under Expansion limits) is on. A link to a canvas is never updated by itself.

The investigation report (Export menu) is one HTML file for what is on screen: a summary, the findings with their reasons, the transactions in time order with inputs and outputs, the wallets, the graph as a picture, where and when every transaction was fetched, and the method and limits. It embeds the evidence as data and states its SHA-256, so a reader can check the file was not changed afterwards (tools/verify_report.py).

A link to the canvas (Export menu, Link to this canvas) copies a link that opens what is on screen for anyone you send it to. The canvas itself is packed into the address after the #, so nothing is stored anywhere and the browser sends that part to no server; whoever has the link can read everything in it, so treat it like the workspace file. It holds at most the number of vertices set beside the button (5 to 500, 50 by default: about 4,000 characters, which chat and mail carry). Over the limit it keeps the vertices nearest START, ring by ring along the lines, and tells you how many were left out; a link that would be too long for chat is cut the same way. It carries the vertices with their amounts and times, your labels and tags, and the picture (layout, colouring, the trace). It leaves out your notes unless you tick Include my notes, what outside services said about a wallet, groups you folded and what you hid. Whoever opens it gets it like an imported file: on an empty workspace the canvas as it was, otherwise merged in, and Undo import takes it back. A big transaction (a CoinJoin, say) arrives with only the inputs and outputs that were on screen: Hopline says how many transactions are only partly there, their details show how much of each is on the canvas, and Show backward or Show forward loads the rest (no pattern is checked for a transaction until all of it is there). A transaction the link cuts carries the short names of the patterns your Hopline found on it (CoinJoin, consolidation, batch, round amount, swap memo, a peel step), so the reader sees them at once: drawn dashed with (sender), shown in the details as the patterns the sender saw, and not counted in the Findings, the report or the assistant's evidence, because they have not been checked there; loading the transaction in full replaces them with what the data says (a few dozen characters of link for each). Only patterns your own analysis found travel, not marks you received in a link. When the reader should get everything, use Link to these transactions, IDs only. A link made from a copy that is opened from your disk opens only on that computer.

Label packs (left panel) import lists of wallets and names from a CSV (address,label,category,url,note) or JSON file, such as an exchange's addresses, or OFAC's sanctions list (SDN_XML.ZIP, SDN_ENHANCED.ZIP or SDN_ADVANCED.ZIP), which is read directly. They appear as known (pack name) with a gold ring, stop an auto-expand like any known wallet, and can be switched off or removed. Export writes your own labels and tags in the same format to share with a colleague. A pack is someone else's claim, not a finding. A list that says what kind of service a wallet is also tags it when it first appears on the canvas: the built-in list marks its exchanges, so Binance or Coinbase get EXCH and Fixed Float gets SWAP, and a pack's category can say Exchange, Mixer, Market, Gambling, Swap or Service. It happens once, so what you change or remove stays; a wallet with a tag of your own is left alone, and a file you open is shown as saved. Switch it off, or tag what is already there, under Label packs > Tags from the lists.

Re-layout places every vertex again (and releases the ones you dragged). The four are in the Layout menu (and the right-click menu of the empty canvas). Spread and Tighten keep the arrangement and change only the room: every vertex moves 30% further from, or closer to, the middle of what is on screen (where x is time, only the heights change); press again for more, and Fit (F) shows it all. Declutter moves apart only the vertices whose shapes, labels, badges or handles touch at the current zoom, and the ones that sit on the line of an edge they are not an end of or under its amount, and leaves everything else where it is. What you dragged gives way last: next to a vertex you did not drag, the other one moves; only when two dragged ones touch, or a dragged one sits on a line, does it move, as little as it takes, and it stays pinned where it lands. All three are one step that Undo (Ctrl+Z) takes back.

Analysis looks for patterns in what is loaded: CONSOL (many inputs gathered into one or two outputs), BATCH (a few inputs paying many outputs), COINJOIN? (several wallets' inputs and several outputs of exactly the same value to different addresses), PEEL (a run of transactions that each pay a smaller amount, more than dust, out of a single coin and pass the rest on) and ROUND (an output that is a round amount, at least 0.01 BTC and a multiple of 0.0001 BTC unless you change that under Analysis: a number somebody chose, where a wallet computes an amount such as change to the last satoshi; often the payment, with the other output the change, but a service paying a fixed amount, a policy or a test gives the same, so it says nothing about who or what chose it; it is left out for CoinJoin-like, consolidation and batch transactions, for the same amount to three or more recipients and for spending from a service wallet, and a round payment into a service wallet is kept) and SWAP (an OP_RETURN in THORChain's swap-memo format, =:ETH.WBTC:0x…: the payment is to be swapped into that asset on another chain and paid out to that address; it is what the sender wrote, not proof that the swap was carried out, and it can sit on a transaction of any other shape; the Hand-offs list names it when the trail from the reference reaches one, and the destination is a lead to follow on the other chain). SWAP ID is the other form: an OP_RETURN that is just 0x and 64 hex digits, the request ID a cross-chain service such as Relay writes on a Bitcoin payment; it does not say where the money went, so the transaction's details offer Look up in Relay (a link that opens Relay's page in a new tab and tells Relay which request you are looking at; not offered over Tor), and the wallet that was paid is the thing to check, then tag as SWAP. A transaction that carries either form is drawn with an orange ring (the colour of the SWAP tag), at any zoom, and its SWAP name comes first. A peel chain is named after the transaction it starts at (P-65a1) and has one colour, so both stay the same whatever else is loaded. Each pattern is also drawn as a thin ring round the transaction, in the pattern's colour (the first one innermost, so two patterns are two rings), and the rings show at any zoom; the names are written above the transaction where they fit, up to three lines in all with START and its tag, and point at or select a vertex to read every name and its chain name. Each kind can be switched off under Flag patterns on transactions. Detections, under the findings in the right-hand panel, lists every pattern found, oldest first, with its reason: filter it by kind or by chain, click a row to select that transaction and bring it into view, or copy the list. Pick a chain there (or open one of its steps) to light it up on the graph with numbered steps, show just that chain as a trace, or follow it further. A transaction's details also say which output most likely returns to the sender, and why; that output's edge is coloured amber. Clusters group addresses that were spent together in one transaction, which usually means one owner, and are drawn with a dashed ring in one colour; CoinJoin-like transactions are left out, and you can leave out any other by hand. All of it is heuristic: it shows its reasons and none of it is proof.

Routes and open ends (Findings): each known wallet says whether money ran between it and the reference (the first starting point, or the vertex you pick under Relative to, which is in the Findings and also in the Route to part of a wallet's details, where every starting point, tagged vertex and wallet with a name, yours or a list's, is offered): ◀ upstream (its money reached the reference) or ▶ downstream, with the number of transactions. Click it to light the route: each coin followed to the transaction that spent it, never by matching addresses, shown in the trace (Ctrl+Z takes it back) and listed in the Findings with Copy route. It is the shortest route, the one with the fewest transactions; Find other routes there looks in what is loaded for up to four more between the same two vertices, each found by leaving out one transaction of the ones before, and lists them shortest first (a route across a service wallet after the others) so that you can light one at a time. It is not a promise that these are every route there is: one that needs something not loaded yet is not in the list. A route is not carried across a service wallet such as an exchange unless there is no other way, and it says so; a step that merges many inputs is named. A route shows the money could have travelled that way, not who controls the wallets between, and no route only means none in what is loaded: search upstream or downstream loads from both ends, within the Auto-expand limits, until a route appears or it runs out. Open ends list where the trail from the reference is still open (outputs never looked up, spenders or funders not loaded) with Continue from these, which follows them with the Auto-expand settings. Service hand-offs list where the trail meets a service wallet (a deposit or a withdrawal), and a wallet that a sanctions or ransomware list names that it passes (marked named); with several starting points they run from each of them (every row says which: start, and its route button starts there) unless you picked one under Relative to, and a transaction that is both a hand-off to a service and carries a swap memo or a request ID is one row with the memo noted on it, as a table to copy or download as CSV, and the report and the assistant evidence carry it. Suggested names offer a list's name, or a label you gave, for wallets spent together with a named one (a guess: nothing is named until you choose Name them). In the details of every wallet and transaction the Route to part is there as soon as there is a reference: the route, or no route in what is loaded with search upstream and search downstream, and Use as reference, which makes that vertex the reference in one click (the same choice as Relative to; with no trace, a vertex is the reference only while it is the one selected, and the button keeps it). A wallet with thousands of transactions says that only the newest are loaded. The grey Not on screen chip counts what is loaded but not drawn and lists the named wallets, hand-offs and open ends among it; the report says at the top how many loaded vertices it leaves out.

Assistant gives an AI assistant the evidence and checks what it says. Copy for assistant copies the instructions and the evidence as text (triage, a draft of the findings text, an explanation of the selected vertex, or a challenge of the findings) to paste into any assistant. The findings come from the analysis; a model only reads, ranks or words them. Check ids compares every transaction id and address in an answer with the workspace and names the ones that are not there, which is how a made-up id is caught; when an id is only a clipped or slightly different copy of one that is in the workspace, the result says so and shows the id it probably meant. When the question names a wallet, the evidence lists the transactions it spent in (up to 12) with their largest outputs, patterns and likely change, so the model can say where the money went. Ask the local model does it with a model on this computer (Ollama, LM Studio, llama.cpp): only localhost or 127.0.0.1 is accepted, no key is sent, nothing leaves the machine. A model's text is a draft, not evidence.

Auto-expand follows the money several transactions in one go, forward or backward, from the selected vertex, stopping at the limits you set (hops, transactions, requests) and at labelled wallets or CoinJoins. Follow chooses every output, the largest, the likely change, or a peel chain. In the Trace layout everything it loaded is shown and one Ctrl+Z takes it back.

Right-click a wallet or transaction for its actions: tag it (EXCH, THREAT, SWAP for a swap or bridge service, …), look a wallet up in Arkham (with your own key, through the proxy) or open Arkham's page for it in a new tab (Check in Arkham: no key, and Arkham is told what you are looking at), load more. Tags give a vertex a colour, a shape and a badge; set them next to the label in the details (VICTIM is blue and points down, THREAT is red and points up). A vertex you wrote a note on carries a small yellow note at its lower right.

Previous / Next under the graph step along the money: from a transaction to the wallets it paid (or that paid in), from a wallet to the transactions that spent from it. One choice moves at once; several open a list.

Keys: [ previous, ] next, C controls (in full screen, over the graph), D details, T time line, B box select, Ctrl+A select all, Ctrl+Z undo, Del hide, Esc deselect (or leave full screen), F fit (also the button beside Undo and Redo), M full screen, / search.
