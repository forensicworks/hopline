# Roadmap

Ideas and known gaps for Hopline, in no particular order inside each section. Nothing here has a date. Size is a rough guess: **S** = under a day, **M** = a few days, **L** = a project.

## Data sources and intelligence

- [ ] **One interface for sources of wallet names.** Label packs, the local Arkham proxy and any future source would follow one contract (a list of addresses in, entries with label, category, source and time out), with the result kept per source on the wallet and the sources named in the report. The rules stay as they are: a name is a claim, nothing is applied automatically, and a lookup that sends an address to a third party asks first. Today Arkham is a special case in `public/js/hopline-external.js`. **M**
- [ ] **Check the Arkham look-ups against a real API key.** The reply is parsed from the field names Arkham documents; the raw reply is always kept on the wallet, so a mismatch is visible. If a real reply looks different, the parsing needs a small fix. **S**
- [ ] **Settle the built-in wallet list** (`public/data/known-addresses.js`). Reviewed for what a computer can check (checksums, spelling, `python tools/review_known_addresses.py`). Still open: 11 addresses carry a second owner as an alternative name, one differs from the mining-pools list, and no entry has a source or a date; a name is a claim, not proof. **S**
- [ ] **More shipped packs.** OFAC and the UK Sanctions List (both sanctions lists, switched on), Ransomwhere (CC BY 4.0), the mining pools list (MIT) and a chosen part of the GraphSense tag packs (MIT) ship now, the last three switched off (see [sources.md](sources.md)). The same files and list can carry other open sources, each with its licence, credit and date shown: Israel's seizure orders (published as documents, mostly Tether), more GraphSense packs once where their tags come from has been read, and a pack of your own cases from seizure documents. A source goes in only after its terms are read, as one more entry in `SOURCES` in `tools/build_packs.py`, and the weekly refresh workflow then keeps it current; the pack format already has the fields (`licence`, `attribution`, `asOf`, `sourceUrl`). **M**

## Wallet overview (`public/wallet.html`)

- [ ] **The chart and the counterparties in the chosen currency.** The ledger can show amounts in a currency; the balance chart and the biggest-counterparties list are in Bitcoin only. **S**
- [ ] **Follow a wallet cluster further on its own.** *Look further* loads the newest transactions of up to 25 other wallets each time it is pressed; following the group several rounds deep, with a clear stop, is not built, and the group is only as complete as what was loaded. **M**
- [ ] **Read a wallet's balance automatically when it is selected.** The details now say "not loaded yet: press Load balance to read it"; reading it by itself is one request per wallet you click on, which matters on a rate-limited public API. **S**

## Workspace

- [ ] **A change guess on one sign counts as low.** A guess that rests on a single sign (the only output of the inputs' address type, or a known wallet on the other side) is still called medium and is followed by Auto-expand. On the synthetic cases a medium guess on one sign is right 89.5% of the time, on two signs 99.5%, and the weak one is "same address type" alone (84%); on real traffic 66% of the guesses rest on one sign (`docs/benchmark-results.md`). Capping them at low would make medium mean two agreeing signs. Decide with the real-wallet data (`docs/benchmark-wallets.md`), which is the first labelled data that is not synthetic. **S**
- [ ] **As one vertex outside the Trace layout.** *Show on graph* and *+ show* work in every layout now; folding rows into one group vertex (*As one vertex*) still exists only in the Trace layout. **M**

## Bigger projects

- [ ] **Benchmark the heuristics: what is left.** Done: the harness, the synthetic regtest cases, a sample of the real chain, and one documented case (`docs/benchmark.md`, results in `docs/benchmark-results.md`, `docs/benchmark-base-rates.md` and `docs/benchmark-cases.md`). Waiting for a person: real wallet software on signet or testnet4 (the tool is built, the data needs wallets and faucet coins: `docs/benchmark-wallets.md`), and more documented cases (each needs the court document or a source that quotes its transactions to be read). Then, on a new seed and a new sample: recalibrate the confidence tiers, and try a minimum amount for the equal outputs of a CoinJoin (both flags on the real sample were dust-sized batches). **L**
- [ ] **A ready-made way to run your own Esplora** (Bitcoin Core with an Esplora or electrs index, packaged with Docker), so a team can drop the public API limits. The README says what it needs (roughly 440 GB of index, about 1 TB free while indexing). **L**
- [ ] **A machine-readable interface: what is left.** The evidence summary, the prompts, the check of an answer and a command-line tool exist (`docs/interface.md`), and so do *Ask the local model* and the optional *Claude* option in the workspace, both tested against stand-in servers only. Still to do: try the local option against real local models (Ollama, LM Studio, llama.cpp) and tune the prompts and the size of the evidence for small context windows; and a small local server so a script does not need Node. Any model feature stays optional and off by default; the evidence goes only to a model on this computer, except through the Claude option, which is off whenever the page opens, shows the exact text and asks before every send. **M**
- [ ] **Run the Claude option once against the real API.** It was built from the API's documentation and tested against a stand-in for `api.anthropic.com`; nobody has sent it a real request with a real key. Do it on a public or testnet workspace, look at the raw reply if anything differs, and fix what is found (the browser must be allowed to call the API directly, the refusal fallback and the model list are the parts to watch). **S**
- [ ] **Let an assistant act on a workspace, with approval for every step.** Today an assistant (a local model or Claude) only reads: it is given the evidence and its answer is checked. The next step is for it to propose actions in plain language (load this transaction, expand forward three hops, stop at a labelled wallet, hide these vertices) that Hopline shows as a list of exact requests, with where each would be sent and how many look-ups it costs, and runs **only after the person approves each one** (or one named batch). It must not run anything on its own, not follow instructions found in labels, notes or label packs, and not go past the limits the person set under Expansion limits; every approved step goes into the activity log and can be undone like any other load. The approval step comes first and is tested on its own before any model is connected to it; Claude and local models then use the same one. **L**
- [ ] **Other blockchains.** Bitcoin only for now; widening it waits until people have used Hopline and say what they need. The model, the API client and the analysis are Bitcoin-only (inputs and outputs, UTXO rules such as common-input clustering). The cheapest next step would be another UTXO chain with an Esplora-style API (Litecoin); Ethereum and Tron need a different model. **L**
